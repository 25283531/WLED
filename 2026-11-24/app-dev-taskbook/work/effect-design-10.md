# 新增 10 个动态灯效：设计方案（只设计，不写代码）

> 本文只出方案。动 FX 注册表与 `MODE_COUNT`，**必须等 M1（统一效果表）落定后再实现**；
> 实现时新效果追加在压缩后的表尾（预计 id 189…198）。

## 0. 通用约定（10 个效果全部遵守）

### 0.1 尺寸自适应：不写死 9×23

- 一律在运行时取：`cols = SEGMENT.vWidth()`、`rows = SEGMENT.vHeight()`，以及段在全局矩阵中的位置/映射方向。
  不出现 `9`、`23`、`207` 之类的字面量。
- 归一化坐标：`ux = x * 256 / cols`（0–255 表示一圈）、`uy = y * 255 / max(1, rows-1)`。
  所有几何参数（半径、宽度、阈值）都按 `cols` / `rows` 的比例给出，不按像素数。
- 圆柱几何假设：只对「周向环绕、纵向连续、上下端封闭」做优化；
  - 周向：`wrap = true` 时才用环绕距离 `d = min(|dx|, cols-|dx|)`；
  - 纵向：连续渐变，两端做端部衰减（`edgeGuard(uy)`）；
  - 非方形：`cols` 与 `rows` 独立归一化，不假设像素是正方形。
- **范围**：本期只针对 2D 圆柱灯体，不做 1D 降级，也不做极小尺寸（如 9×3）的特殊退化。

### 0.2 纵向方向（重要，需先复核一个现存问题）

- 已知实测：三锚点中逻辑 `(0,22)` 显示在第 1 列**最底**，`(1,22)` 空位、`(2,22)` 在第 3 列最底 →
  **逻辑 `y=22` = 物理底，`y=0` = 顶**。
- 因此本文统一约定：`y = 0` 是**顶行**，「底部」= `rows-1`；`posY = (rows-1-y)*255/(rows-1)` 表示离地高度。
- ⚠️ **现存 `mode_lumi_aurora`（`FX.cpp:5221`）把 `y=0` 当底部**（`baseRing` 画在 `y<=1`，注释写「0 最底部」），
  与上述锚点矛盾，怀疑「极光之舞」上下颠倒。实现前先实测一次（点亮 Aurora，看青色底座在顶还是底），
  统一到本文约定；这是 10 个新效果的共同前置项。

### 0.3 亮度与安全

- 全局 `bri` 受 §0.4 约束（彩色 ≤60% → `bri=153`），效果内部再套一层 `LUMI_MAXV = 200`（≈78%）用于白热像素，
  避免「白热核心 + 全局亮度」叠加超预算。所有输出走 `nscale8`，不做 `qadd8` 饱和到 255。
- 第 46 颗空位（逻辑 `(1,22)`）在可见列内。凡是「底部一行连续」的视觉（脉冲环、扫描环、雨滴溅落）
  必须容忍该像素不亮，不做逐像素依赖、不做邻位补光。

### 0.4 数据结构与内存

- 每效果状态一律 `SEGENV.allocateData(bytes)`，只申请一次（`SEGENV.call == 0` 时初始化），切效果自动释放。
- 单效果状态 ≤ **512 B**（DRAM，`d_malloc` 路径）；fire 例外，`cols*rows` 上限截到 **1024 B**（超限自动降采样）。
- 不新增全局数组、不新增静态大对象、不用 PSRAM（207 像素没必要）。

### 0.5 每帧预算（ESP32-S3 @240 MHz，实测基线 43 fps ≈ 23 ms/帧）

| 项 | 目标 |
|---|---|
| 单效果像素循环 | ≤ 1.5 ms/帧（207 px，即 ≤ 7 µs/px） |
| `perlin8` 调用 | ≤ 64 次/帧（每次约 1–1.5 µs，超了就改查表/低频复用） |
| `sin8_t/cos8_t` | ≤ 4×像素数，且按行/列预计算，不在内层重复 |
| 浮点 | 禁止在内层循环；统一 `uint8_t/uint16_t` 定点 |
| 音频效果额外 | ≤ 0.6 ms（FFT 已由 usermod 算好，效果只读 16 个 bin） |

## 1. 林间萤光 `Lumi Forest`（自然配色 #1）

- **取色（参考图 2 苔原/林间）**：底 `#1E5B2E` 深苔 → `#3FA34D` 叶绿 → `#8BD450` 嫩芽 → `#C8E85A` 黄绿；
  萤火点缀 `#FFE9A8` 暖白。渐变方向：底深顶亮（灯体从苔绿升到嫩黄）。
- **算法**：`base = ramp(uy + 0.18*sin8(ux + t))`，纵向为主；叠加 `N` 只萤火：
  每只 `{px, py, phase}`，`px += drift`，`py = py0 + 8*sin8(phase+t)`，亮度 `sin8_t(phase*3)` 呼吸，3×3 内缩回。
- **数据结构**：`struct {uint8_t px, py, ph, drift;} ff[12]` = 48 B。
- **音频**：无。
- **参数**：速度（`speed`，默认 96）、萤火数量（`intensity` → 1–12，默认 7）、呼吸幅度（`c1`，默认 128）。
- **圆柱适配**：萤火 `px` 周向环绕；纵向不环绕；上下各 1 行做 `edgeGuard` 端部衰减。
- **差异点**：不是「噪点铺满」，而是**低对比渐变 + 少量暖点**，与 `Fireflies`(80)/`Noise`(70) 的满屏噪点不同。
- **尺寸自适应**：渐变位置由 `uy`（`rows` 归一化）决定、萤火漂移用 `ux`（`cols` 归一化），换尺寸不改代码。
- **预算**：207 px × 1 次 ramp 查表 + 12×9 萤火写入 ≈ 0.35 ms。

## 2. 暮色晚霞 `Lumi Dusk`（自然配色 #2）

- **取色（参考图 1 沙丘日落）**：`#4FD8E8` 天青 → `#7B5BE0` 紫 → `#E85CC4` 品红 → `#FFC24A` 琥珀 → `#FF7A2E` 橙 → `#E23A1E` 赤。
  渐变方向：**顶冷底暖**（与图一致）。
- **算法**：三层水平带（压缩/拉伸随 `rows`），每层叠加 `sin8(ux*k + t*sp)` 慢波 + `perlin8` 云层调制；
  「落日」是一个随 `sunY` 缓慢升落的高斯光斑，只在光斑附近把颜色推向暖白。
- **数据结构**：无（纯函数），仅 `SEGENV.aux0` 存 `t`。
- **音频**：无。
- **参数**：速度（`speed`，默认 60）、云层强度（`intensity`，默认 120）、太阳高度（`c1`，默认 128 → 循环升落）。
- **圆柱适配**：水平带**必须周向环绕**（带是整圈的，接缝不能断开）；纵向不环绕，顶部略降亮度模拟天空。
- **差异点**：与现有 `Sunrise`(104)/`Colorwaves`(62) 的区别是**分段色带 + 云层调制 + 落日光斑**，不是单一渐变。
- **尺寸自适应**：三层色带按 `rows` 三等分（`rows<6` 时按比例压缩而非固定 3 行），云层与落日尺寸按 `cols/rows` 比例缩放。
- **预算**：207 px × (2–3 次 sin + 1 次 ramp) ≈ 0.5 ms。

## 3. 极地冰川 `Lumi Polar`（自然配色 #3）

- **取色（参考图 3 极光冰湖）**：底 `#E855B8` 品红 → `#9B5BE8` 紫 → `#5B7CF0` 蓝 → `#3FD0F0` 青 → 顶 `#2FE38A` 极光绿；
  星点 `#E8F6FF`。
- **算法**：纵向底渐变 + 两道「极光帷幕」：帷幕中心 `cx(uy) = sin8(uy*shear + t)`，亮度按周向距离衰减，
  再乘 `perlin8` 做帘状撕裂；顶部撒 `M` 个静态星点，按 `sin8` 微闪。
- **数据结构**：`struct {uint8_t x,y,ph;} star[8]` = 24 B。
- **音频**：无。
- **参数**：速度（`speed`，默认 80）、帷幕宽度（`intensity`，默认 110）、星光数量（`c1` → 0–8，默认 5）。
- **圆柱适配**：帷幕**周向必须环绕**（否则接缝处出现硬边）；纵向顶/底各 2 行衰减。
- **差异点**：现有 `Aurora`(38)/`Polar Lights`(174)/「极光之舞」都是横向丝带；本效果是**纵向帘幕 + 星点**，且配色来自参考图 3。
- **尺寸自适应**：帷幕中心 `cx(uy)` 与宽度按 `rows/cols` 归一化，星点坐标按 `cols/rows` 比例生成，换面板不用改参数。
- **预算**：207 px × (1 sin + 1 perlin + ramp) + 8 星 ≈ 0.55 ms。

## 4. 真实壁炉火焰 `Lumi Hearth`

- **算法**：热力场 + 火舌驱动（不是均匀呼吸）。
  1. 底部 1–2 行注入热量：`heat[i] = f(perlin8(x*3 + t*2), 全局抖动)`；
  2. 每帧上移一格并做 `(heat[y-1]*3 + heat[y+1]) / 4 - cooling`，模拟热扩散；
  3. **火舌**：每列叠加两道相反方向的行波 `tongue = sin8(uy*rows*0.6 + t + x*37)`，只在 `heat > 128` 时抬升，形成舔动；
  4. 着色：`t<80` 顶部熄灭（黑）→ `#FF5A1E` 橙红 → `#FFB43C` 亮橙 → `t>200` 根部 `#FFF3D0` 白热。
- **数据结构**：`uint8_t heat[cols*rows]`（9×23=207 B；通用 `cols*rows` 截断 1024 B，超限按 2 倍降采样）。
- **音频**：无。
- **参数**：冷却速度（`speed`，默认 100）、火舌高度（`intensity`，默认 140）、抖动（`c1`，默认 90）。
- **圆柱适配**：**不做周向环绕**（接缝处火焰断开反而自然）；最左/最右列各降 15% 亮度，避免接缝双倍亮。
- **差异点**：现有 `Fire 2012`(66)/`Fireworks`(42)/`Noise Fire`(149) 都是 1D 或噪声焰；
  本效果是**2D 热扩散 + 白热根/橙红中/熄灭顶的分层**，满足「火舌舔动而非均匀呼吸」。
- **尺寸自适应**：`heat[]` 按 `cols*rows` 运行时申请；注入行数 = `max(1, rows/12)`、冷却量按 `rows` 缩放，保证高度变化后观感一致。
- **预算**：207 × (读2+写1+2 sin) ≈ 0.9 ms；DRAM 207 B。**本组最重，但仍远低于 1.5 ms 目标。**

## 5. 熔岩灯 `Lumi Lava`

- **算法**：4–7 个「色团」（metaball）。每团 `{cx, cy, r, hueT}`，用 `perlin8` 极慢漂移；
  场内 `field = Σ (r*r) / (d*d + 1)`（`d` 为周向环绕距离 + 纵向距离）；
  `field > 阈值` 时按 `hueT` 混色（深红 `#B3001B` → 橙 `#FF6B1A` → 品红 `#E0457B`）；气泡是独立上升的亮点。
- **数据结构**：`struct {uint8_t cx, cy; uint16_t r;} blob[8]` = 32 B；`struct {uint8_t x,y;} bub[6]` = 12 B。
- **音频**：无。
- **参数**：团块数量（`speed` → 4–7，默认 5）、融合阈值（`intensity`，默认 120）、上升速度（`c1`，默认 90）。
- **圆柱适配**：团块距离**周向环绕**（熔岩绕柱流动）；纵向 `cy` 限制在 `[1, rows-2]`，避免贴边割裂。
- **差异点**：现有 `Plasma`(97)/`Blobs`(121)/`Metaballs`(154) 是噪声或 3D 投影；本效果是**少量大色团缓慢融合/分离 + 气泡**。
- **尺寸自适应**：团块半径用 `min(cols, rows)` 的比例（如 `r = 0.18 * min(cols,rows)`），阈值随 `rows` 归一化，换尺寸不改代码。
- **预算**：207 px × 5 团 ≈ 1.0 ms；44 B 状态。

## 6. 深海波光 `Lumi Caustics`

- **算法**：三重干涉场：`w = sin8(ux*3 + t) + sin8(uy*5 - t*2) + sin8((ux+uy)*2 + t*3)`；
  取「脊线」`ridge = 255 - |w - 384|` 得到网状光斑；色带 `#012A33` 深水 → `#0E6B7A` 暗青 → `#7FF2FF` 亮斑。
- **数据结构**：无（纯函数）。
- **音频**：无。
- **参数**：速度（`speed`，默认 70）、网格尺度（`intensity`，默认 100）、光斑锐度（`c1`，默认 150）。
- **圆柱适配**：`ux` 用 `x*256/cols` **严格环绕**（否则接缝处光网错位）；纵向不环绕，底部略暗。
- **差异点**：现有 `Ripple`(98)/`Waverly`(191)/`Lake`(75) 是同心圆或噪声；本效果是**折射网纹**（caustics），亮斑是线不是团。
- **尺寸自适应**：三重干涉场的波数按 `cols/rows` 归一化（`ux*k`、`uy*m` 中的 `k/m` 用比例而非像素数），网眼密度随面板尺寸保持恒定。
- **预算**：207 px × 3 sin + 1 ramp ≈ 0.5 ms。

## 7. 环形频谱喷泉 `Lumi Spectrum Fountain`

- **音频量**：
  - `bass = max(fftResult[0..2])`，`mid = max(fftResult[3..7])`，`high = max(fftResult[8..15])`；
  - 平滑：`bassS += (bass-bassS) * (bass>bassS ? 0.55 : 0.12)`（快攻慢放）；
  - 瞬态：`samplePeak` 置位，或 `volumeSmth` 环比增量 > 阈值（去抖 120 ms）。
- **算法**：
  - 低频 → **底部厚环**：环高 `h = map(bassS, 0, 255, 1, rows/2)`，暖色带 `#FF3D00→#FFB000`，整圈同步；
  - 中高音 → **星光**：每帧按 `mid/high` 概率从 `y ≈ rows*0.35` 附近发射粒子，
    `vy = -(1 + high/64)` 向上、`vx = ±` 周向散开，寿命 12–20 帧，亮度按寿命衰减；
  - 瞬态 → **扩散波纹**：以底部为源，`radius` 每帧 +2，`alpha` 每帧 ×0.85，最多 3 道。
- **数据结构**：`struct {uint8_t y,w,life;} ring[3]`=9 B；`struct {int8_t vx, vy; uint8_t x,y,life;} p[16]`=64 B。合计 73 B。
- **参数**：低频增益（`intensity`，默认 180）、星光数量（`c1` → 0–16，默认 10）、瞬态灵敏度（`c2`，默认 140）、速度（`speed`，粒子速度）。
- **圆柱适配**：环是**整圈**（天然环绕）；粒子 `x` 周向环绕；纵向不环绕，顶部 2 行淡出。
- **差异点**：不是把 16 个 bin 画成 9 根柱子（`GEQ`/`Freqwave` 的做法），而是
  **频段→高度、音量瞬态→扩散波纹**，视觉上「底部推起暖浪 + 上部炸开星光」。
- **尺寸自适应**：环高上限 = `rows/2`、粒子发射带 = `rows*0.35`、粒子寿命按 `rows` 缩放，全部由运行时尺寸推导。
- **预算**：207 px + 16 粒子 ≈ 0.6 ms。

## 8. 心跳/呼吸脉冲环 `Lumi Pulse Ring`

- **音频量**：节拍用 `samplePeak`（usermod 提供的峰值标志）为主，辅以 `volumeSmth` 上升沿；
  耐火期 220 ms；平时 `bassS` 只驱动背景呼吸。
- **算法**：静止时背景 `~4%` 亮度缓慢呼吸（`sin8`，周期 4 s）；
  踩中节拍 → 从底部生成 1 道（强拍 2 道）光环，`y` 以 6–10 px/帧上行，
  环体 1–2 px、后方 6–10 px **余晖拖尾**（沿 `y` 做 `nscale8` 递减，不需要额外缓冲）；
- **数据结构**：`struct {uint8_t y, speed; uint16_t born;} rings[4]` = 16 B。
- **参数**：背景亮度（`c1`，默认 10）、光环速度（`speed`，默认 160）、拖尾长度（`intensity`，默认 8）、灵敏度（`c2`，默认 140）。
- **圆柱适配**：光环为**整圈**；上下端各 1 行收边（顶部不硬切）。
- **差异点**：现有 `BPM`(68)/`Pulse`(162)/`Ripple Peak`(148) 是整屏闪或同心圆；本效果是**单向上升环 + 拖尾**，背景几乎全暗。
- **尺寸自适应**：环速按 `rows` 归一化（`speed * rows / 23`），拖尾长度 = `max(2, rows/3)`，换高度后上升时间一致。
- **预算**：207 px × 3 道环 ≈ 0.4 ms。

## 9. 光环扫描/雷达 `Lumi Scanner`

- **音频量**：无（纯动效），可选把 `volumeSmth` 映射到扫描速度（`mi` 开关）。
- **算法**：2–3 道**1 px 极细**水平环，在 `y` 上做三角波 ping-pong（端点用 `sin8` 缓动，不是生硬折返）；
  环经过的行「充能」到 `charge[y] = 255`，之后每帧 `charge[y] = scale8(charge[y], 244)`（约 6 s 余辉），
  按 `charge` 决定该行亮度（`#7FE9FF` 青白）。
- **数据结构**：`struct {uint8_t pos; int8_t dir;} scan[3]` = 6 B；`uint8_t charge[rows]`（23 B，通用截 64 B）。
- **参数**：环数（`speed` → 1–3，默认 2）、扫描速度（`intensity`，默认 120）、余辉时长（`c1`，默认 200）。
- **圆柱适配**：整圈水平线（天然环绕）；上下端点用缓动，不硬折。
- **差异点**：与 `Scan`(10)/`Scan Dual` 的区别是**2D 水平环 + 充能余辉**，且环极细（1 px），是「雷达扫过」而非「行进点」。
- **尺寸自适应**：环数不超过 `max(1, rows/8)`，扫描速度按 `rows` 归一化，`charge[]` 按 `rows` 运行时申请。
- **预算**：207 px（只读 charge）+ 3 环 ≈ 0.25 ms。

## 10. 雨滴/数据流 `Lumi Rain`

- **算法**：每列维护 1–2 滴：`{y, speed, len, bright}`；头部 `#DCEFFF` 冷白、尾部 `#7FD8FF` 冰蓝并沿 `y` 衰减；
  落到底行 → 在该列与相邻 2 列做 6 帧涟漪（`splash[col]` 计数），涟漪亮度低、不跨接缝。
- **数据结构**：`struct {uint8_t y, sp, len;} drops[cols*2]`（9 列 = 54 B，通用截 128 B）；`uint8_t splash[cols]`（9 B）。
- **音频**：无（后续可把 `high` 映射到雨量，作为增强项，不列入首版）。
- **参数**：雨量（`speed` → 列内滴数，默认 1）、下落速度（`intensity`，默认 140）、拖尾长度（`c1`，默认 10）。
- **圆柱适配**：**不做周向环绕**（雨滴直落）；接缝两列减少一滴，避免视觉上「双倍雨」。
- **差异点**：现有 `Meteor`(76)/`Rain`(43)/`Drip`(96) 是 1D 或 2D 通用；本效果是**竖直冷白长尾 + 落底溅落**，气质是「数据流」。
- **尺寸自适应**：滴数 = `cols`（每列 1 滴，可调 2）、拖尾 = `max(3, rows/3)`、下落速度按 `rows` 归一化，`drops[]`/`splash[]` 按 `cols` 运行时申请。
- **预算**：207 px + ≤18 滴 ≈ 0.35 ms。

## 11. 实现顺序与风险

### 11.1 顺序（每批 CI 编译一次 + OTA 一次）

1. **前置**：M1 落定；复核 §0.2 的纵向方向（顺带修 Aurora 的 `y=0` 假设）。
2. **批次 1（无缓冲、无音频）**：2 暮色晚霞、3 极地冰川、6 深海波光 → 验证周向环绕接缝与纵向端部。
3. **批次 2（带状态缓冲）**：4 壁炉、5 熔岩灯、10 雨滴 → 验证 `allocateData` 与尺寸推导。
4. **批次 3（音频）**：7 频谱喷泉、8 脉冲环、9 雷达 → 先静音确认无自激闪烁，再放音乐调参。
5. **APP 侧**：批次 3 通过后一次性重生成 catalog + 10 张预览图。

### 11.2 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 纵向方向搞反 | 见 §0.2，现有 Aurora 已疑似颠倒 | 先实测再写，统一 `bottomRow()` 辅助 |
| 周向接缝 | 首尾列在背面接缝，正视只看到中间列；环绕写错会在背面裂开 | 用 `ux = x*256/cols` 的环绕距离，不用 `abs(x1-x2)` |
| 第 46 颗空位 | 逻辑 `(1,22)` 在可见列底部 | 底部连续视觉不得依赖单像素；不做邻位补光 |
| 音频参数误判 | 同 GEQ：`sx=200` 时看起来「没反应」 | 每个音频效果默认参数必须上机验证可见律动；文档写清默认值 |
| FFT 量纲差异 | 不同 bin 的 `fftResult` 动态范围不同 | 全部走「快攻慢放 + 阈值」归一化，不直接用绝对值 |
| 内存分配失败 | `allocateData` 可能失败 | 失败即 `FX_FALLBACK_STATIC`，不进入半初始化状态 |
| 亮度超限 | 白热像素叠加 | 内部 `LUMI_MAXV=200`，AC/全局 `bri` 双重限制 |
